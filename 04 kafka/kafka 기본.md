
#### 토픽

- 파티션으로 구성된 로그파일. 하나의 토픽은 여러개의 파티션으로 나뉠 수 있다.
- 데이터의 이름표. 문서에서는 폴더에 비유
- 논리적인 개념인 듯하다. 사실 디스크에 남는 로그는 파티션 단위로 남는다.
	- ex) my-topic-0, my-topic-1 (뒤에숫자가 파티션 번호)

- Key-Value 기반 메시지를 담는다.
	- Value는 어떤 타입의 메시지도 가능 (문자열, 숫자, object, json, protobuf)
- 메시지는 순차적으로 물리적인 File에 Write됨 (Offset 기반 append)

#### 파티션

- 토픽은 여러개의 파티션을 가질 수 있음
	- 카프카 병렬성능과 가용성의 핵심요소
	- 메시지는 개별 파티션에 분산 저장된다
- 개별 파티션은 정렬되고, 변경할 수 없는 레코드로 구성된 로그 메시지이다. 
  (distributed, immutable, partitioned / log message)
- 개별 레코드는 offset으로 불리는 일련 번호를 할당받는다.
- 개별 파티션은 다른 파티션과 완전히 독립적이다.

#### 병렬 분산처리 

- 메시지는 개별 파티션에 분산저장 된다. 
- 가용성을 위해 클러스터 내에서 브로커들 끼리 복제할 수 있다.
	- replication factor=3 → 클러스터를 구성하는 브로커중 3개의 브로커에 데이터를 복제
	- 쓰기가 이루어지는 파티션을 리더, 복제된 파티션을 팔로워라고 한다. 
	 (리더 팔로워는 파티션 단위이다)


### 메시지 순서보장

- 카프카는 하나의 파티션 내에서만 메시지 처리 순서를 보장한다.

### 메시지 키

- 특정 key값을 가지는 메시지는 특정 파티션으로 고정되어 전송된다
	- **이 Key는 유일식별 Key가 아님. 파티션 고정용도이다.**
	- 파티션을 고정하는 이유는 처리순서를 보장하기 위해서이다.
	- `hash(key) % N` 으로 파티션을 결정한다. 
		- 파티션 수가 변경되면 같은 메시지키라도 다른 파티션으로 갈 수 있기 때문에, 운영중 파티션 추가는 주의가 필요하다.

### 파티셔너와 배치

카프카 프로듀서는 메시지를 생성하고 바로 보내지 않는다. 
파티셔너가 배치큐로 메시지를 보내고, 배치큐에서 메시지를 모아놨다가 보낸다.
이 배치큐는 브로커의 파티션과 1대1 대응된다.

**파티셔너**: `Partitioner` — 메시지가 어느 파티션으로 갈지 결정
**배치 큐 전체**: `RecordAccumulator` — 파티션별 배치 큐를 관리하는 컴포넌트
**개별 배치 큐**: `Deque<ProducerBatch>` — 파티션마다 하나씩 존재. 브로커와 1대1 대응
**Sender**: 분리된 스레드에서 배치를 꺼내 브로커로 전송

**배치큐는 카프카 프로듀서, 즉  카프카 클라이언트 모듈에 있다. 브로커가 아님**

### 키가 없는 메시지에 대한 분배 전략

- **라운드 로빈**
	- kafka 2.4이전 기본 파티션 분배전략
	- **배치큐**에 라운드 로빈 방식으로 메시지를 분배함.

- **스티키 파티셔닝**
	- kafka 2.4이후 기본 파티션 분배전략
	- **배치큐**에 스티키 방식으로 메시지를 분배함.
		- 하나의 배치가 찰거나 일정시간이 지나기 전까지 같은 배치큐로 계속 보냄
		- 배치가 차거나 일정시간이 지나면 다른 배치큐로 전환함
	- 라운드 로빈 방식은 배치가 잘 안차서 비효율적이라서 스티키 방식이 default가 됨.
		- 배치가 안찼는데 계속 보내면 작은 단위의 요청을 여러번 보내게되고, 네트워크 I/O횟수가 늘어나게 됨
		- ex) 100개전송을 할 때 
			- 스티키 =  배치큐1개에 100개 몰아넣고 1번 전송(I/O 1회) 
			- 라운드로빈 = 34개 33개 33개  I/O 3회)

### 컨슈머 그룹, 리밸런싱

- **컨슈머 그룹** 
	- 하나 이상의 컨슈머로 구성된 논리적 그룹
	- 그룹 내 컨슈머들이 파티션을 나눠서 소비한다.
	- 서로 다른 컨슈머 그룹은 같은 토픽을 구독해도 분리되어 독립적으로 동작한다.
		- 오프셋 관리와 리밸런싱 둘 다 독립적이다.


- **리밸런싱**
	- 컨슈머 그룹내 컨슈머 변화가 있을 때 마다 파티션과 컨슈머의 조합을 변경하는 작업
	- **하나의 파티션은 단 하나의 컨슈머에만 할당된다**
		- 따라서 파티션 갯수보다 컨슈머 수를 많이 만들어도 남는 컨슈머는 놀게된다.
